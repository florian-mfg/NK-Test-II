# Frontpage local redesign

The Frontpage now builds a responsive editorial collage over pure white. The other routes and the MP4 playback controller were preserved as they stood before this request. No deployment, commit, push, CMS content or schema changes were made.

1. **Navigation:** the existing header grid is positioned at `top: 50dvh` (with a `50vh` fallback) and translated upward by half its own height. This centers the complete group while retaining its original horizontal columns, spacing, Raglan font and links. Home-specific rules also preserve centering on mobile. Navigation remains at z-index 50, above collage layers 1–7. The shared binary contrast controller composites the image luminance and opacity over white for the home header; it uses the existing black/white thresholds without blend effects or backing panels.
2. **Desktop input:** accumulated Euclidean mouse distance advances progress at 1 image per 1,200 CSS pixels. Coalesced pointer samples count toward distance. Rendering batches into requestAnimationFrame; no easing or autonomous slideshow runs after movement stops. Direction changes continue advancing. Leaving the viewport resets the pointer baseline, not progress.
3. **Mobile input:** holding a non-navigation touch advances at 0.28 images per second. Multiple fingers share one clock. Final release accounts for the remaining elapsed time and cancels the frame loop. Release, cancel and resume retain the exact composition. Navigation and dialog controls are excluded; the existing home touch-action rule prevents page scrolling.
4. **Rolling sequence:** all images enter from zero opacity. Once six have appeared, the newest fades in while the oldest fades out using the same progress fraction. **As explicitly chosen in the clarification, seven images may be visible during that simultaneous crossfade; exactly the six newest remain when it finishes.** Image 7 replaces image 1; image 8 replaces image 2. The original 20-item order loops, without duplicate sources inside the window. Removed elements are released; at most seven media elements remain in the collage DOM. The bounded original image warm cache is retained.
5. **Placement:** twelve deterministic placement variations use different viewport-relative maximum sizes and asymmetric anchors. Images fit those bounds at their native aspect ratio, with no crop, rotation, mirroring or distortion. Narrow viewports use adjusted bounds. Newer images layer above older ones, with overlap and white negative space. Source dimensions prevent a load-time sizing jump for the local images. Resizing recalculates placement without resetting input progress.
6. **Files changed for this request:** `frontpage-media.js` (new ordered data and aspect ratios), `frontpage-media-fade.js` (collage renderer and input batching), `style.css` (home-only layout), `index.html` (data script), `app.js` (home contrast setting), `contrast.js` (home-only composition sampling). Updated tests: `tests/frontpage-media-fade.test.cjs`, `tests/frontpage-media-fade-browser.test.cjs`, `tests/frontpage.test.cjs`, `tests/contrast-browser.test.cjs`, `tests/mp4-fallback-browser.test.cjs`. Preview artifacts: `reports/frontpage-desktop.png` and `reports/frontpage-mobile.png`.
7. **Validation:** frontend suite: 140 passed, zero failed, 26 opt-in checks skipped. Chrome regression suite: 17 active checks passed across the full run and targeted rechecks; three separate live-production checks skipped. Checks cover white background, navigation midpoint/clickability, mouse progression, exact input freezing, touch hold/release/resume, multi-touch, cancellation, replacement order, crossfade opacity, loops, bounded DOM, varied positions and sizes, native aspect ratios, responsive resizing, overflow, cleanup and other portfolio routes. Official typography and existing mobile navigation checks passed. Known black/white image pixels verified home navigation contrast. Additional desktop and mobile checks used the actual localhost website without mocked page responses and verified input progression, freezing and navigation. `git diff --check` passed.
8. **Future Sanity integration:** media data lives in its own module, separate from interaction and rendering. `FrontpageMediaFade.init(layer, sequence)` accepts replacement ordered records (`type`, `src`, optional `aspectRatio` and `poster`). A future adapter can pass normalized CMS media here. Current home hero fields remain ignored, and all existing Sanity integration elsewhere is unchanged.
